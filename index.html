Load the application

The demo is the actual bundle plus a browser-side API. It runs locally, so nothing you do here touches a server — which is also why it is safe to click freely.

What is real: the interface, every screen, the navigation, the charts and both arcade games, over a snapshot of the actual seed catalogue. What is not: the server. There is no scrypt, no AES-256-GCM, no hash chain, no rate limiter and no session binding here — those belong to the Node process, and a page in a browser cannot have them. The Security Centre therefore shows sample posture.
What is inside

Three products and a platform

The library and the counter were Java Swing over MySQL. Both arcade games were C. All four knew nothing about each other. They share one schema now, and one set of rules.

Library 📚

Catalogue, issue and returns

Catalogue with ISBN and shelf, issue and return with due dates, a 15-day loan period, ₹2 per day overdue, reservations, and a fine total that survives the round trip.

Store 🛒

Counter, billing and reports

Point of sale with barcode SKUs, stock that cannot go negative, low-stock alerts, and a bill whose maths is the interesting part: subtotal, then discount, then tax on the reduced amount — never tax on the original.

Arcade 🎮

Number Guessing and Snake

Both C projects kept their rules and gained difficulty levels. Number Guessing rejects a submit faster than 1.2 seconds; Snake · Water · Gun plays best of three. Both write to one leaderboard.

Security 🛡

The centre, reporting on itself

Twenty-nine controls with live values rather than a static claim, an append-only audit chain sealed outside the database, rate-limit buckets, session state and a threat score.

Security

The part that was actually built

Most of this is not decoration. These are code paths, and the test suite attacks them on every run.

🔑

scrypt with a pepper outside the database

N = 216, r = 8, p = 2 — 64 MiB per hash — then an HMAC pepper held in a key file that is gitignored and never enters the database. Reuse of the last three hashes is refused.

🔑

Phone numbers sealed at rest

Borrower contacts and bill phone numbers are stored as AES-256-GCM ciphertext. Exact lookup still works through a deterministic blind index, so ciphertext is never pattern-matched. A test scans the database files for recoverable plaintext.

🔗

A tamper-evident audit chain

Every event extends a SHA-256 hash chain with a Merkle root and a proof-of-work nonce. Rewriting history breaks the links, and the chain head is sealed to a file outside the database so a wholesale rewrite is detectable.

🔒

Sessions that cannot be replayed

Tokens are split: the store keeps only a public id and SHA-256 of the secret. Sessions bind to IP and User-Agent, idle out after 30 minutes, cap at five per user, and are destroyed by a password change.

✓ Proven by the suite

  • 165 tests pass on every run — 45 smoke, 98 security, 22 crypto
  • CSRF, traversal, injection and malformed bodies are each attacked
  • Unknown users pay the full hash cost and get an identical error
  • A failed body never puts a stack trace in a response
  • The database files contain no recoverable plaintext PII

! Honest limits

  • The in-memory session store does not survive a restart or scale past one process
  • There is no TOTP second factor
  • The ledger seal is a file, not append-only storage
  • The audit chain is not a substitute for real logs shipped to a SIEM
  • Untested against a real attacker with time and a network position
Run it yourself

Clone, start, done

There is no npm install step because there are no dependencies. You need Node 22.5 or newer — node:sqlite does not exist before that. 

# Windows PowerShell
git clone https://github.com/Abhijeet-Kumar-Prajapati/Campus-Nexus.git
cd Campus-Nexus
node server.js            # or double-click start.bat

# macOS / Linux
git clone https://github.com/Abhijeet-Kumar-Prajapati/Campus-Nexus.git
cd Campus-Nexus && node server.js

# it prints the URL and two demo logins:
#   admin / admin123   staff / staff123

✓ What you get on first run

  • 20 titles, 25 products and a full bill history, seeded automatically
  • Its own HMAC pepper and data key, generated into a gitignored folder
  • A SQLite file created from the schema in src/schema.sql
  • The bundled build already committed, with subresource integrity hashes

! Before you expose it

  • The demo logins are printed on startup — change them or delete the accounts
  • Sessions live in memory, so a restart signs everyone out
  • SECURITY.md lists every control and what it does not cover
